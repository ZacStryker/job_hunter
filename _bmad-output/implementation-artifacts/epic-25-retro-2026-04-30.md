## Challenges

### Edge Cases Reaching Review Instead of Being Caught During Implementation
Four of the six review patches were bugs detectable by asking "what happens if the user submits empty, wrong type, or boundary values?":
- Missing `res.ok` guard — key stored on any non-401, non-5xx Anthropic response
- NaN `imapPort` — `Number('')` = 0, passes client but fails Zod on server
- Double `encrypt()` — each upsert called `encrypt()` twice (store, then set again), resulting in double-encrypted ciphertext
- `beforeLoad` swallowing — non-ok, non-401 status from `/api/onboarding/status` silently rendered the onboarding page

**Root cause:** Implementation mental model focused on happy path and error path, but not malformed-input path.

### `beforeLoad` Error-Swallowing is a Systemic Pattern
The `onboardingRoute` `beforeLoad` guard only handled `401` and `res.ok`. All other responses were silently ignored. Review caught this in 25.2, but the same pattern exists in `loginRoute` and `registerRoute`. This is not isolated to Epic 25.

### Retro Action Item Lost Between Retro Document and Story File
Epic 24 retro flagged as a **critical path item**: update Epic 25 to include `imap-poller.ts` per-user secret reading. The action item was documented but never reconciled into the 25.1 story task list before dev started. The dev agent worked from the story file as written — which covered `/sync` but not the background poller. Result: `imap-poller.ts` still reads from global env vars.

**Root cause:** No mechanism to enforce that retro action items requiring code change are added to the next story's task list before SM hands it to dev.

## Significant Discovery — `imap-poller.ts` Gap Was a False Alarm

**Retro session:** The Epic 25 retro flagged that `imap-poller.ts` still read from global env vars, requiring a fix before Epic 26. This was listed as the sole critical path item.

**Post-retro investigation (2026-04-30):** `imap-poller.ts` was **deliberately removed** during the Epic 9-12 commit ("Remove imap-poller in favour of email-fetch-service"). No background IMAP poller has existed since then. Email sync is on-demand only via `POST /api/messages/sync`, which Story 25.1 correctly updated to read per-user credentials from `user_secrets`. `IMAP_HOST`/`IMAP_USER`/`IMAP_PASS` env vars are not referenced anywhere in the codebase.

**Root cause of false alarm:** `project-context.md` contained a stale entry — *"IMAP polling: live in `src/server/services/imap-poller.ts`"* — that reflected a design removed months earlier. The Epic 24 retro was written from that stale reference.

**Resolution:** No code fix needed. Documentation corrected:
- `project-context.md` — stale `imap-poller.ts` reference replaced with accurate description of on-demand sync
- `.env.example` — dead `IMAP_POLL_INTERVAL_MS` line removed

## Key Lessons Learned

1. **Review is a safety net, not a replacement for implementation-time edge-case thinking** — NaN port and missing `res.ok` are both caught by a simple "what does the user submit wrong?" pass during implementation
2. **`beforeLoad` guards need explicit non-ok handling** — the pattern of only handling 401 and success leaves server errors silently misbehaving; this is a systemic pattern across multiple routes
3. **Retro action items must land in story files** — insight documented in a retro document that never reaches the story task list is effectively lost; the SM must close the loop during story prep
