`normalizeText`, `detectStatus`, and `findMatchingJob` were all exported as pure functions — directly testable without mocking IMAP or touching the DB. This produced 3 focused unit test suites before integration tests ran.

### Review caught 8 real defects before they shipped

## What Didn't Go Well

### Story 6.2 had 4 review patches — the most in any single story to date

**MIME decoding missing:** `mailparser` wasn't in the original spec. Raw `bodyParts['1'].toString()` fails for HTML-only or transfer-encoded emails. This is a real-world email protocol detail that should have been in scope at story creation.

**DB query outside try/catch:** `db.select().all()` ran before the outer `try` block, creating an unhandled rejection risk in the `setInterval` async callback. A known pattern from prior files wasn't followed at the outer level.

**Missing deduplication:** Every 5-minute poll re-processed all messages since the cutoff, inserting duplicate `status_events` rows on repeat runs. Deduplication is fundamental to polling service correctness — it should have been an explicit AC, not a review catch.

**UTC/local date arithmetic:** `new Date(job.dateApplied + 'T00:00:00')` vs IMAP envelope UTC dates shifted the ±3-day match window by up to 24h. The fix (`T00:00:00Z`) is the same lesson from Stories 4.3, 5.1, and 5.2 — but the 6.2 story spec itself used `T00:00:00`, propagating the error.

Charlie (Senior Dev): "The timezone issue is on the spec, not the dev. The dev followed the implementation reference exactly and got the bug. Spec quality issue."

### The `T00:00:00Z` lesson has appeared in 4 stories and isn't yet a formal invariant
Stories 4.3, 5.1, 5.2, 6.2 — all required the same fix. It lives in dev notes as a convention but not in `project-context.md` as a hard rule. Dev notes aren't checked before implementation; project context is.

### 13 deferred items accumulated with no scheduled cleanup
The IMAP service has a growing tail: no graceful shutdown, `setInterval` not idempotent, potential concurrent poll overlap, no minimum interval clamp, unsanitized error logging risk. Each deferral was correct for a personal single-user tool — but the list is now 13+ items with no scheduled triage.

---

## Key Insights

1. **Polling services need deduplication in AC at story creation.** Re-processing is inherent to polling — if dedup isn't in the acceptance criteria, it won't be implemented, and review has to catch it.

2. **`T00:00:00Z` must be a hard invariant in project-context.md.** Four stories, same fix. Elevate it from a dev note convention to a documented rule that every agent reads before implementation.

3. **MIME decoding is a required spec element for email-processing stories.** "Fetch the body" is insufficient. "Parse with `simpleParser()` for charset/transfer-encoding safety" must be in the story scope.

4. **Dev notes as implementation contracts continue to work.** Complete code references + explicit guards + test patterns = clean execution. Maintain this pattern.

5. **Review is catching real bugs, which means the spec is still producing defects.** 8 patches is good evidence that review works. The goal is to move correctness earlier, into the story spec, so review is the last line — not the primary line.
