# Story 41.1: DB Schema, Migration & Blacklist API

Status: done

## Story

As a user running discovery,
I want the system to have a company blacklist backed by a DB table and a CRUD API,
so that my blacklist entries are persisted and accessible to both the discovery pipeline and the config UI.

## Acceptance Criteria

1. **Given** `bun start` runs the migration runner
   **When** the runner completes
   **Then** a `company_blacklist` table exists with columns: `id INTEGER PRIMARY KEY AUTOINCREMENT`, `user_id INTEGER NOT NULL REFERENCES users(id)`, `company_name TEXT NOT NULL` (stored lowercase), `created_at TEXT NOT NULL`
   **And** a `UNIQUE(user_id, company_name)` constraint exists on the table

2. **Given** an authenticated user calls `GET /api/blacklist`
   **When** the response is received
   **Then** the status is 200 and the body is an array of `BlacklistEntry` objects (`{ id, userId, companyName, createdAt }`) belonging only to that user
   **And** an empty array is returned (not null) when the user has no entries

3. **Given** an authenticated user calls `POST /api/blacklist` with body `{ "companyName": "Acme Corp" }`
   **When** the request is processed
   **Then** the status is 201 and the response body is the created `BlacklistEntry` with `companyName` stored as `"acme corp"` (lowercased)

4. **Given** an authenticated user calls `POST /api/blacklist` with a company name already in their blacklist
   **When** the request is processed
   **Then** the status is 409 and the body is `{ "error": "Company already blacklisted" }`

5. **Given** an authenticated user calls `DELETE /api/blacklist/:id` with an ID that belongs to them
   **When** the request is processed
   **Then** the status is 204 and the entry is removed from the table

6. **Given** an authenticated user calls `DELETE /api/blacklist/:id` with an ID belonging to a different user
   **When** the request is processed
   **Then** the status is 404 and the body is `{ "error": "Not found" }`

7. **Given** any `/api/blacklist` endpoint is called without a valid session cookie
   **When** the request is processed
   **Then** the status is 401 (auth middleware rejects before the handler runs)

8. **Given** business-logic and HTTP contract tests exist
   **When** the test suite runs (`bun test`)
   **Then** all tests pass; tests cover list/create/delete, duplicate rejection (409), wrong-user delete (404), and unauthenticated access (401)

### File 4: `src/server/routes/api-blacklist.ts` — Full Implementation

```ts
import { Hono } from 'hono'
import { and, eq } from 'drizzle-orm'
import { db } from '../../db/client'
import { companyBlacklist } from '../../db/schema'
import { blacklistEntryInputSchema } from '../../shared/schemas'
import type { AppEnv } from '../types'

const app = new Hono<AppEnv>()

app.get('/', (c) => {
  const userId = c.get('userId')
  const rows = db.select().from(companyBlacklist).where(eq(companyBlacklist.userId, userId)).all()
  return c.json(rows)
})

app.post('/', async (c) => {
  const userId = c.get('userId')
  let body: unknown
  try {
    body = await c.req.json()
  } catch {
    return c.json({ error: 'Invalid JSON body' }, 400)
  }
  const parsed = blacklistEntryInputSchema.safeParse(body)
  if (!parsed.success) {
    return c.json({ error: parsed.error.issues[0]?.message ?? 'Invalid request body' }, 400)
  }
  const companyName = parsed.data.companyName.trim().toLowerCase()
  const existing = db.select({ id: companyBlacklist.id })
    .from(companyBlacklist)
    .where(and(eq(companyBlacklist.userId, userId), eq(companyBlacklist.companyName, companyName)))
    .get()
  if (existing) {
    return c.json({ error: 'Company already blacklisted' }, 409)
  }
  const result = db.insert(companyBlacklist).values({
    userId,
    companyName,
    createdAt: new Date().toISOString(),
  }).returning().get()
  return c.json(result, 201)
})

app.delete('/:id', (c) => {
  const userId = c.get('userId')
  const rawId = Number(c.req.param('id'))
  if (!Number.isInteger(rawId) || rawId <= 0) {
    return c.json({ error: 'Invalid id' }, 400)
  }
  const entry = db.select().from(companyBlacklist).where(eq(companyBlacklist.id, rawId)).get()
  if (!entry || entry.userId !== userId) {
    return c.json({ error: 'Not found' }, 404)
  }
  db.delete(companyBlacklist).where(eq(companyBlacklist.id, rawId)).run()
  return c.body(null, 204)
})

export default app
```

**Implementation notes:**
- Duplicate detection uses an explicit `SELECT` pre-check, not a UNIQUE constraint violation catch — consistent with rest of API and gives a predictable error shape
- DELETE returns 404 for both "not found" and "wrong user" — same security pattern as other routes (avoids leaking whether ID exists)
- `companyName` is trimmed+lowercased at insert time; stored value is always lowercase
- 204 response uses `c.body(null, 204)` — established project pattern (used in api-auth.ts, api-admin.ts)

```ts
process.env.DB_PATH = ':memory:'

import { describe, test, expect, beforeAll, beforeEach } from 'bun:test'
import { Hono } from 'hono'
import { Database } from 'bun:sqlite'
import type { AppEnv } from '../../server/types'

const { default: blacklistRoute } = await import('./api-blacklist')
const { db: prodDb } = await import('../../db/client')
const prodSqlite = (prodDb as unknown as { $client: Database }).$client

// Main test app — auth bypassed, userId=1
const blacklistApp = (() => {
  const w = new Hono<AppEnv>()
  w.use('*', (c, next) => { c.set('userId', 1); return next() })
  w.route('/', blacklistRoute)
  return w
})()

// App with auth middleware for 401 test — no userId set, no session cookie provided
const { authMiddleware } = await import('../../server/middleware/auth-middleware')
const authApp = (() => {
  const w = new Hono<AppEnv>()
  w.use('*', authMiddleware)
  w.route('/', blacklistRoute)
  return w
})()

const CREATE_TABLE = `
  CREATE TABLE IF NOT EXISTS company_blacklist (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL DEFAULT 1,
    company_name TEXT NOT NULL,
    created_at TEXT NOT NULL
  )
`

beforeAll(() => {
  prodSqlite.run(CREATE_TABLE)
})

beforeEach(() => {
  prodSqlite.run('DELETE FROM company_blacklist')
})
```

**Required test cases** (all ACs covered):

- `GET /` returns empty array when no entries
- `GET /` returns only entries belonging to the requesting user (insert user_id=1 and user_id=2; request as user 1; only see user 1's entries)
- `POST /` inserts entry, returns 201 with lowercased companyName
- `POST /` lowercases and trims input (e.g., `"  Acme Corp  "` → stored as `"acme corp"`)
- `POST /` returns 409 when company already in user's blacklist
- `POST /` returns 400 for empty companyName
- `DELETE /:id` removes entry and returns 204
- `DELETE /:id` returns 404 when ID belongs to different user (insert as user_id=2, delete as user 1)
- `DELETE /:id` returns 404 for non-existent ID
- `GET /` returns 401 when no session cookie (use `authApp`, no cookie set)

**401 test note:** The auth middleware returns 401 immediately if no `session` cookie is present — it does NOT query the DB in this case. So `authApp` does not need any DB tables to test the 401 path.

**User-scoping test note:** The `blacklistApp` sets `userId=1` for all requests. To test user isolation (AC: 2, 6), insert rows directly via `prodSqlite.run("INSERT INTO company_blacklist (user_id, company_name, created_at) VALUES (2, 'other corp', '...')")` and assert they are not returned/deleted.

### Architecture Compliance

- New table follows project schema conventions: snake_case columns, `id` as integer autoincrement PK, `user_id` FK, no `updated_at` (not needed for append-only table)
- Route file follows `kebab-case.ts` naming: `api-blacklist.ts`
- Route sub-instance exported as `default` from a `new Hono<AppEnv>()` — same as all other routes
- Auth handled by global `app.use('/api/*', authMiddleware)` in `src/index.ts` — the route file itself does NOT add auth middleware
- All user data isolation via `c.get('userId')` from context — never from request body or params
- Error shape: `{ error: string }` only — no envelope, no `{ message }` shape
- `BlacklistEntry` type exported from `src/shared/schemas.ts` only — never redefined inline

### Testing Architecture

- Two test layers: business-logic (route mounted with fake userId middleware) and 401 (route mounted with real auth middleware)
- Test DB: `:memory:` SQLite — `process.env.DB_PATH = ':memory:'` MUST be set before any production module loads
- Schema DDL: created via raw `prodSqlite.run(CREATE_TABLE)` in `beforeAll` — no migration runner
- Isolation: `DELETE FROM company_blacklist` in `beforeEach`
- Assertion style: assert both response status AND body shape; assert `error` key present and `message` key absent on errors
