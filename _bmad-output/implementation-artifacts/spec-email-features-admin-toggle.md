## Intent

**Problem:** Email features (Messages page, inbox/Gmail-label mapping, and the onboarding "Email Setup" step) are always present, forcing every new user through email connection even though the default desired experience is email-free.

**Approach:** Introduce a single **global** admin feature flag `emailFeatures` (default OFF), mirroring the existing `source_settings` pattern exactly. When OFF: hide the Messages nav link + Inbox Mapping config card, redirect those routes, skip the onboarding Email Setup step, and reject the corresponding API endpoints server-side. Admins flip one Switch on the Admin Users page to re-enable everything together.

## Boundaries & Constraints

**Always:**
- The flag is **global** (no `userId`) — mirror `source_settings`: a generic `feature_settings(feature TEXT PRIMARY KEY, enabled INTEGER NOT NULL DEFAULT 0)` table.
- **Default OFF.** Absence of a row = disabled. Server read logic treats "no row OR `enabled=false`" as off.
- Public read `GET /api/feature-settings` available to any auth'd user (NOT admin-only) — returns `{ emailFeatures: boolean }`. Needed for client gating.
- Admin write `PATCH /api/admin/feature-settings/:feature` gated by the existing `/api/admin/*` blanket `adminMiddleware`.
- Server enforcement via a new `emailFeaturesMiddleware` (modeled on `admin-middleware.ts`) returning `403 { error: 'Email features are disabled' }` when off. Gate: `/api/messages`, `/api/config/inbox-mappings`, `/api/config/gmail-mappings`, `PUT /api/onboarding/imap`, and `/api/onboarding/gmail/*`.
- Leave the admin flag read/write endpoints themselves ungated. Leave `GET /api/onboarding/status`, `PUT /api/onboarding/anthropic`, `PUT /api/onboarding/indeed`, and the LinkedIn/Indeed browser routes ungated (not email).
- Follow project conventions: Drizzle `casing: 'camelCase'`, `{ error: string }` shapes (no envelope/`message`), explicit `null`, arrays for collections, `bun:test`, strict TypeScript, shared types only from `src/shared/schemas.ts`.

**Ask First:**
- If `bun run db:generate` produces a migration that conflicts with or alters any existing table beyond adding `feature_settings`.

**Never:**
- Do not add a per-user override — strictly a single global admin toggle.
- Do not delete existing messages, mappings, or user email secrets when the flag is off — data is preserved, only hidden/blocked.
- Do not rely on UI hiding alone — server endpoints must enforce.
- Do not invent a new settings mechanism — mirror `source_settings`.

## Design Notes

**Default-off without a seed:** No migration seed row. `GET` and the middleware both compute off when the row is absent. The admin PATCH upserts the row on first toggle. This keeps the migration a pure `db:generate` CREATE TABLE (respecting the project's "generate, don't hand-write migrations" rule) and avoids `_journal.json` desync.

**Why prefetch in `protectedRoute.beforeLoad`:** `messagesRoute`/`configProfileInboxMappingRoute` `beforeLoad` must read the flag synchronously via `queryClient.getQueryData` — exactly how `adminUsersRoute` reads `['session']`. Prefetching the flag in the parent `beforeLoad` (alongside session) guarantees it is cached before children evaluate. `.catch(() => {})` keeps a transient flag-fetch failure from blocking the whole protected tree (fail-safe: children then treat it as off → redirect home, consistent with default-off).

**Hono wildcard gating:** `app.use('/api/messages/*', ...)` does NOT match the bare `/api/messages` list endpoint, so register both the bare and `/*` path for each gated mount. Onboarding email endpoints are `PUT /imap` (bare `/api/onboarding/imap`) and `gmail/*` (connect, callback, labels, DELETE) — gate `'/api/onboarding/gmail/*'` and `'/api/onboarding/imap'`. Do NOT blanket-gate `/api/onboarding` (it hosts ungated anthropic/status/indeed endpoints).

**Onboarding step remap:** Step state stays `0,1,(2),3`-shaped but the "ready" screen renders on `readyStep` (3 when email enabled, 2 when disabled) so `StepIndicator` (which highlights `i === currentStep` across `totalSteps` dots) stays correct with 3 dots when disabled.
