## Successes

- **Edge-case input validation discipline applied consistently** — the "before marking any handler task complete, ask what happens with empty, wrong type, or boundary input?" discipline from Epic 25 retro appeared as an explicit checklist in both 26.1 and 26.2 dev notes. Measurable result: 14 review patches in 26.1 → 8 in 26.2 → 3 in 26.3.
- **Dual `userId`/`sessionUserId` architecture** — non-obvious design decision that correctly solved the "admin can't exit impersonation" problem. `sessionUserId` tracks the real admin; `userId` tracks the effective (impersonated) user. Admin middleware checks `sessionUserId`, allowing exit even while impersonating a standard user.
- **Route ordering discipline** — registering `/impersonate/exit` before `/impersonate/:id` in Hono prevents "exit" from being captured as an `:id` parameter. Explicitly documented in dev notes to prevent future regression.
- **Security state guards caught in review** — 26.1 review caught and patched: admin self-deactivation (400 guard), last-admin demotion block, nested impersonation rejection (409), self-impersonation block, admin-to-admin impersonation policy decision.
- **Zero regressions, zero production incidents** — third consecutive epic at this quality level.
- **Live verification** — Stryker confirmed admin UI rendering, invite key "Used" status correctly shows no actions (per AC #9), used-by email resolved correctly via JOIN query.

## Challenges

### State Invariant Thinking Lags Input Validation Thinking

26.1 had 11 implementation-time patches in code review. Input validation guards were well-applied (edge-case checklist), but "what system states should never be allowed?" was not checked during implementation. Examples caught only in review:
- Admin self-deactivation (locks self out)
- Last-admin demotion (removes all admin access from system)
- Self-impersonation
- Nested impersonation

**Root cause:** The edge-case mental model is scoped to input validation. State invariant checking ("what invariants must always hold?") is a distinct discipline not yet built into the implementation habit.

**Impact:** High review volume in 26.1 — 14 patches — before the story was done. These were detectable during implementation with a simple state-invariant pass.

### Cross-Cutting Fixes Still Not Landing in Story Files

Epic 25 retro action item #3 — fix `beforeLoad` defensive pattern across loginRoute, registerRoute, onboardingRoute — was documented, referenced in 26.2 dev notes, and deferred again as "pre-existing pattern." This is the second consecutive epic where this fix was flagged and not executed.

**Root cause:** A cross-cutting fix that isn't a numbered task in a story file is invisible to the dev agent. The SM must add it as an explicit task during story prep — not as a note, not as a dev notes reference.

**Impact:** A known bug pattern (server errors silently swallowed in route guards) carries into Epic 27 for the third time.

## Key Lessons Learned

1. **Edge-case input validation discipline works and is now embedded** — when a checklist becomes part of the story dev notes template, it gets applied. The improvement from 14 patches (26.1) to 3 patches (26.3) is evidence.
2. **State invariant checking is the next discipline to build in** — "what inputs are invalid?" and "what states should never exist?" are separate questions; we're good at the first, still developing the second.
3. **A retro action item that isn't a story task is invisible** — two epics of evidence. The fix is simple: SM converts cross-cutting retro items to numbered tasks during story prep, not notes.
