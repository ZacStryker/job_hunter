## Challenges

### Story 24.3 Was Significantly Larger Than Expected
Scoped as "add userId FK to four tables and scope queries" — in reality required touching 30+ files, writing a manual migration (DEFAULT 1 backfill), and discovering mid-review that the existing `(company, job_title)` unique index was not user-scoped, forcing an unplanned fourth migration (0022).

**Root cause:** Multi-tenancy migrations have two separable risk surfaces — schema migration and query scoping — that were bundled into one story.

### Manual Migration Timestamp Bug (Silently Skipped Migrations)
Migrations 0021 and 0022 were given timestamps from 2025 (~1745xxxxxxx) copied from an example in the dev notes, while all prior migrations had 2026 timestamps (~1777xxxxxxx). Drizzle's migrator skips entries whose `when` predates the latest applied migration — both migrations were silently skipped on any database that had run prior migrations.

**Impact:** `user_id` columns and per-user unique index were not applied to existing databases. Users would have seen each other's data if deployed without noticing.

**Resolution:** Timestamps corrected; migrations applied correctly.

### Framework Gotchas Consumed Investigation Time
- **argon2 async + sync transaction**: `db.transaction()` callback is synchronous; argon2 must be hashed *before* entering the transaction — not obvious from docs
- **Hono 204 + cookie headers**: Must use `c.body(null, 204)` not `new Response(null, {status: 204})` or `Set-Cookie` headers are silently dropped
- **Drizzle `notNull()` test DDL expansion**: Adding `notNull()` to a schema column causes drizzle to include ALL schema columns in generated INSERT SQL — broke test DDLs across the suite

### Drizzle Snapshot Drift (Ongoing Risk)
Migrations 0012–0018 have no drizzle-kit snapshot JSON files. Running `bun run db:generate` can produce extra DDL for "missing" columns. This risk is still present and must be resolved before Epic 25 schema work begins.

### Discovery Flow CSRF Bug (Found and Fixed in Retro)
`useWebhookStream.ts` was not updated to use `apiFetch` in story 24.4 because it's a streaming hook, not a mutation hook — the 24.4 task checklist listed `use*Mutation` hooks only. The raw `fetch` call sent no `x-csrf-token` header; auth middleware returned 403 on all pipeline trigger POSTs.

**Fixed in retro:** Added `apiFetch` import and replaced `fetch` on line 39 of `useWebhookStream.ts`.

**Stories:** 25.1 (Onboarding API) and 25.2 (Onboarding UI), both backlog.

**Dependencies on Epic 24:**
- `user_secrets` table (24.1) — first production use in 25.1 for encrypted Anthropic API key and IMAP credentials

- Auth routing (24.4) — `onboardingComplete` is hardcoded `true`; 25.1 must wire up real `/api/onboarding/status`

**Significant Discovery — IMAP Poller Gap:**
Epic 25 as currently written stores per-user IMAP credentials in `user_secrets` but does NOT update `imap-poller.ts` to read them. The poller continues using global env vars. A user completing onboarding would have their IMAP credentials stored but silently ignored. **Epic 25 must be updated to include poller per-user secret reading before stories are created.**

**Other preparation needed:**
- `decrypt()` try/catch must be explicit in 25.1 dev notes — GCM exceptions are uncaught and will surface as 500s
- Profile table is not yet per-user scoped — analysis-service uses shared profile for all users (known limitation, not a blocker for Epic 25)

## Key Lessons Learned

1. **Manual migrations need `Date.now()`** — copied example timestamps cause silent skips; this must be explicit in the dev notes template
2. **Cross-cutting stories deserve splitting** — schema migration and query scoping are different risk surfaces; bundling them into one story created a 30-file blast radius with an unplanned extra migration
3. **Streaming hooks are mutation hooks** — any checklist updating "mutation hooks" for CSRF must explicitly include streaming hooks that make POST requests
