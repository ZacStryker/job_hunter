## What Didn't Go Well

### Two accessibility defers shipped knowingly

**`aria-describedby` on `<tr>`:** Radix `TooltipTrigger asChild` injects `aria-describedby` onto the trigger element, which is a `<tr>`. The `row` ARIA role doesn't officially accept `aria-describedby`; some assistive technologies may not surface the tooltip relationship. The specified approach in the story made this unavoidable without violating spec constraints.

**`prefers-reduced-motion` on tooltip animation:** The shadcn `TooltipContent` includes `animate-in`/`animate-out` classes that don't respect `prefers-reduced-motion`. The spec required using the shadcn-generated file without hand-editing it, so this was deferred. A global CSS override would be the fix.

Both items are tracked in `deferred-work.md`. Neither is a blocker, but both are real accessibility gaps.

### Epic 4 retrospective was skipped
Epic 4 had 4 stories including the most complex mutation pattern in the codebase (`useJobMutation` with optimistic update + rollback). Its retrospective was marked `optional` and never run. Whatever lessons lived in those stories are lost. This is a process gap.

## Key Insights

1. **Solid foundations make stories assemble** — Epic 5 was fast because Epics 1–4 did the hard work. Every pattern used in Epic 5 was established and documented in a prior epic.
2. **Export pure functions when they contain business logic** — testable without rendering, no mocks needed, boundary cases easy to pin.
3. **Pattern propagation is working** — `T00:00:00`, loader pattern, `JobDrawer` reuse all applied correctly without re-discovery.
4. **Don't skip retrospectives on complex epics** — Epic 4 had 4 stories and a novel mutation pattern; those lessons were lost.
