Evaluation Guide

A — Minimal

Maximum signal reduction. No decorative framing, no app branding on auth pages. Fastest to build, most focused. Risk: feels generic.

B — Contextual

App name above form cards. Numbered step bar in onboarding. Inline test button next to input. Most "developer tool" feel — matches Vercel/Linear reference.

C — Split

Landing splits value props from CTA. Onboarding uses left sidebar for step context. Best orientation, most layout complexity. Sidebar takes width on smaller screens.

D — Progress

App logo on auth pages. Horizontal progress bar drives onboarding. Test button is idle until key entered. Strongest "forward motion" feeling through the flow.

Note: Admin view shows two distinct patterns — A uses visible inline action buttons (faster, more clickable); C/D uses 3-dot menu + dropdown (cleaner table, slightly more friction). Both are valid for 10-user scale.
